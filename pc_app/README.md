# FerroDSP Lab

Окно исследований: RealSense D415 слева, оптические сигналы металлоискателя справа.
Программа **не меняет DSP, EEPROM и мощность передатчика**. Она использует сохранённый
проект [FerroDSP PC Stream](../сигма_проект/FerroDSP_PC_Stream/FerroDSP_PC_Stream.dspproj) и протокол
`ferrodsp-am-iq-v1` (четыре комплексных канала через стерео S/PDIF).
Проверенная калибровка и описание протокола включены в `resources/`; для запуска
программы старые многогигабайтные записи не требуются. При изменении схемы DSP или
аудиотракта применимость калибровки нужно проверить заново.

## Запуск

Для другого компьютера используйте переносимый выпуск **Windows x64**:
скачайте ZIP из [Releases](https://github.com/neuroandriyanov/FerroDsp/releases),
распакуйте целиком и запустите **`FerroDSP-Lab.exe`**. Python и библиотеки включены;
отдельная установка Python, SigmaStudio и FFmpeg для запуска окна не требуется.
См. [краткую инструкцию](QUICKSTART.md). Архив также можно создать командой сборки ниже в `pc_app/dist`.

Подключаются только D415 и выбранный S/PDIF WASAPI; микрофон и звуковой выход
не открываются. Если устройств нет, окно остаётся доступным и показывает ошибку.
Требуются драйверы устройств Windows, USB 3 для D415 и S/PDIF 96 кГц PCM24.
В EXE настройки и записи сохраняются в `UserData` рядом с программой;
`FERRODSP_DATA_DIR` позволяет выбрать другой каталог. В исходной версии сохраняются
прежние `pc_app/local` и `pc_app/recordings`. Калибровка стенда в ZIP не включается.

Для разработки из исходников нужен Python 3.12 x64:

```powershell
py -3.12 -m venv pc_app/.venv
pc_app/.venv/Scripts/python.exe -m pip install -r pc_app/requirements.txt
pc_app/.venv/Scripts/python.exe pc_app/app.py --connect
```

Команды выполняются из корня репозитория. После создания `.venv` работает
`Запустить лабораторию.cmd`. `start-lab.ps1 -PythonExe C:\path\python.exe`
позволяет явно выбрать интерпретатор. Запуск второй копии с тем же каталогом данных
блокируется; камера и WASAPI exclusive принадлежат одному процессу.

## Сборка для публикации

На Windows x64, в чистой виртуальной среде Python 3.12:

```powershell
py -3.12 -m venv pc_app/.venv
pc_app/.venv/Scripts/python.exe -m pip install -r pc_app/requirements-build.txt
pc_app/.venv/Scripts/python.exe pc_app/build_portable.py
```

Сборщик запускает тесты, создаёт EXE и проверяет его с очищенным `PATH`, затем
записывает ZIP, SHA-256 и отчёт в `pc_app/dist`. Существующий ZIP не перезаписывает.
Новая версия задаётся в `VERSION` и `version_info.txt`.
В ZIP входят исходники, лицензии, описание транспорта и манифест файлов;
`local`, `recordings`, `UserData`, `tmp` и аппаратные опыты туда не копируются.
Не добавляйте ZIP и бинарники в Git: прикрепляйте их к GitHub Release.
Workflow `ferrodsp-lab-windows.yml` собирает и проверяет артефакты на Windows;
публикация релиза выполняется отдельно. Компоненты и их условия распространения
описаны в [THIRD_PARTY.md](THIRD_PARTY.md).

## Перед опытом

1. Включить прибор с проектом передачи I/Q. Для первой проверки EEPROM не нажимать
   F7 в SigmaStudio. Программа покажет качество пилота и декодирования.
2. Оставить камеру и катушку неподвижными. Включены глубина Z16 и RGB BGR8,
   оба 640×480, по умолчанию 30 кадров/с. Цвет совмещается с **родными координатами
   глубины** по заводской калибровке SDK. Поэтому на цветном изображении могут
   появляться чёрные участки, где нет соответствующей глубины.
3. «Точки плоскости»: выбрать минимум три, лучше 5–6 широко разнесённых точек
   **на одной видимой плоской поверхности корпуса катушки**. Не выбирать отверстия,
   края и фон за катушкой. «Принять плоскость» вычисляет нормаль и смещение в 3D.
   СКО выбранных точек — качество подгонки плоскости, а не паспортная точность камеры.
4. «Область измерения»: протянуть прямоугольник под катушкой. Убрать цель и руку,
   нажать «Пустой фон»: сохраняется медиана 15 кадров без заполнения дыр глубины.
5. «Зафиксировать фон фазы»: запомнить относительную фазу в пустом состоянии.
   Исходные I/Q не изменяются; это только отображение графика.
6. Добавить предмет в таблицу, заполнить материал либо «неизвестно», размеры,
   ориентацию, плановую дистанцию и примечание. Выбрать строку и начать запись.
   Таблица и параметры измерения блокируются до остановки; подпись опыта копируется
   в его метаданные. Плановая дистанция не подменяет измеренную камерой.

В столбце ориентации доступен редактируемый список: плоскость либо продольная ось
образца параллельна/перпендикулярна плоскости катушки. Для наклонного положения
укажите угол и используемую ось. Новая строка имеет значение «Не задана» — программа
не предполагает ориентацию до её выбора. Полный текст доступен во всплывающей подсказке.

При следующем запуске геометрия намеренно не включается автоматически.
Если камера и катушка **точно не перемещались**, в «Параметры камеры» →
«Измерение и цвет» можно восстановить сохранённую привязку. Проверяются серийный
номер и внутренние параметры камеры. После любого перемещения нужна новая привязка
и пустой фон. По одному серийному номеру обнаружить перемещение нельзя.

## Расстояние и крестик

Сначала SDK переводит Z16 в метрические 3D-точки. Для нормали `n`, смещения плоскости
`d` и точки `p` зазор со стороны камеры равен `d − dot(n,p)`. Измерение учитывает
наклон катушки. Ручной вариант предполагает строго параллельную камере плоскость;
это приближение явно подписано в окне и метаданных.

Кандидаты должны быть ближе к камере, чем пустой фон, находиться в выбранном ROI и
диапазоне глубины/зазора. Изолированные пиксели и маленькие области отбрасываются.
Среди поддержанных соседними пикселями участков выбирается минимальный зазор.
Крестик имеет **30×30 пикселей исходного кадра**. Подпись расстояния поверх изображения
убрана; крупное цифровое показание над предпросмотром сохраняет исходное измерение.
При отсутствии достоверной цели крестик исчезает, число заменяется прочерком.

Третий график справа показывает расстояние в мм на общей шкале времени с фазой и
амплитудой. Только эта кривая проходит фильтр выбросов: окно из пяти кадров,
центральная медиана и порог `max(15 мм, 3 × 1.4826 × MAD)`. В «Параметры камеры»
можно изменить минимальный порог в мм. Устойчивый переход и равномерное движение
сохраняются; одиночный короткий реальный импульс фильтр тоже может считать выбросом,
поэтому исходное расстояние и отметка замены сохраняются отдельно.

В живом окне результат ожидает два следующих кадра (около 67 мс при 30 кадр/с),
но размещается по времени **центрального исходного кадра**, без сдвига оси времени.
Крупное число остаётся текущим исходным показанием. Через недостоверную глубину
и пропуски кадров фильтр не проходит и расстояние не подставляет. На границах опыта
используется сокращённое окно; крайняя точка без соседей с обеих сторон не заменяется.
Демонстрационное видео использует тот же фильтр и содержит третий график.

Измеряется **ближайшая видимая камерой поверхность**, а не скрытая верхняя сторона
предмета. Толщина предмета не восстанавливается. Рука тоже является поверхностью —
держать её вне ROI. Тонкое кольцо, плоскость которого перпендикулярна плоскости катушки,
и блестящая фольга могут не давать надёжной
глубины; программа не заменяет пропуски выдуманным расстоянием. Нижняя измерительная
граница задаёт программный отбор и не гарантирует работоспособность D415 на ней.

## Настройки и графики

- Цвет, глубина, наложение; независимые коэффициенты непрозрачности. Цвет наносится
  поверх глубины на чёрном фоне: `C*a + D*b*(1-a)`.
- «Параметры камеры»: измерительный диапазон, границы цветовой шкалы, палитра,
  пороги фона/связной области; отдельная таблица всех доступных SDK-параметров
  сенсоров с текущим значением, min/max/step/default и признаком read-only.
  Изменения проверяются драйвером, включая зависимости автоматической экспозиции.
- «Настройки захвата»: D415/серийный номер, 6/15/30 кадров/с, выбор оптического
  WASAPI-входа, запись цветных кадров и демонстрации, окно графиков в ролике,
  поправки времени камеры/аудио и резерв места на диске.
  Числовая глубина и PCM24 сохраняются всегда. Для смены устройства/FPS/поправок времени отключить потоки.
- «Графики и масштаб»: два независимых графика — Δ фазы от фона, относительная
  фаза, амплитуда, I/Q или сырой транспорт S/PDIF; выбор каналов, окно времени,
  автоматический либо заданный масштаб Y. Дополнительно — график расстояния с
  отдельным масштабом Y и общим временным окном. Настройки графиков не меняют исходники.

RX0/RX1 — две половины приёмного тракта; TX катушка/TX усилитель — два разных
измерения напряжения передатчика. В относительной фазе опора — TX катушка.
Её собственная относительная фаза равна нулю. I/Q выдаются 100 раз/с из окон Hann
40 мс. Декодер ждёт ещё 70 мс, чтобы пометить обе стороны обнаруженного скачка
времени. Реальная полоса огибающей около 20 Гц. Сырой S/PDIF здесь содержит
AM-поднесущие и пилот, а не четыре исходных широкополосных АЦП.

## Что записывается

Каждый опыт получает новый каталог `pc_app/recordings/YYYYMMDD-HHMMSS-<id>`.
Существующие опыты не перезаписываются.

| Файл | Содержимое |
| --- | --- |
| `demonstration.mp4` | Видео 1280×640: название/материал/ориентация, изображение 640×480 с крестиком слева, числовой индикатор над изображением; справа фаза, амплитуда и отфильтрованное расстояние; общий таймер |
| `distance-chart.jsonl` | Времена кадров, исходные и отфильтрованные расстояния, достоверность и отметки замены выбросов |
| `demonstration-timeline.jsonl` | Для каждого кадра MP4: время опыта, индекс исходного кадра и разность времён; −1 при отсутствии кадра |
| `demonstration-preview.jpg` | Контрольный кадр готового ролика |
| `analysis.h5` | Общая временная шкала: глубина/XYZ/пиксель, I/Q, амплитуды, абсолютные/относительные фазы, отклонение от фона, маски качества и ссылки на исходники |
| `camera.h5` | `depth_z16` без потерь, метрический масштаб в атрибуте; монотонные метки ПК; совмещённый цвет в JPEG, если включён |
| `camera.jsonl` | Номера глубинных/цветных кадров, родные часы/metadata, время источника и получения на ПК, источник временной метки, измерение и его достоверность |
| `spdif.wav` | Два канала, 96 кГц, PCM24 без преобразования в float на пути записи |
| `audio-timing.jsonl` | Индексы WAV/потока/устройства, сырые позиции IAudioClock и QPC, модель часов, оценка времени первого отсчёта, флаги WASAPI и разрывы |
| `iq.jsonl` | Восемь I/Q, пилот, valid, метки скачков и защитных интервалов, временная привязка |
| `session.json` | Предмет, геометрия, настройки устройств, границы записи, версии исходников, статус completed/incomplete |
| `events.jsonl` | Настройки графиков/фон фазы и итоговые счётчики |
| `background-m.npy` | Пустой фон в метрах |
| `transport-calibration.json` | Копия применённой калибровки AM/IQ |
| `manifest.json` | Размеры и SHA256 всех файлов опыта |

Стоп выполняется асинхронно: сначала дочитываются задержанные буферы, затем
формируется `analysis.h5`, из сохранённых данных собирается демонстрация и считаются
хеши. Окно показывает этап и прогресс видео. Смена предмета и новая запись доступны
после завершения. Закрытие окна во время записи сначала сохраняет опыт.
При потере потока, заполнении очереди или нехватке диска опыт помечается неполным.

Демонстрация использует выбранный вид камеры (цвет/глубина/наложение), каналы графиков
и зафиксированный перед записью фон фазы. Без фона показывается относительная фаза
к TX катушки. Автомасштаб Y рассчитывается по всему опыту и не плавает во время
ролика; ручные пределы соответствующих графиков фазы/амплитуды берутся из настроек.
Окно времени ролика задаётся отдельно в настройках захвата. MP4 кодируется в
H.264/AVC Main, 8 бит, YUV 4:2:0, с индексом в начале файла (`faststart`).
Экспорт проверяет завершение FFmpeg и декодирует весь ролик; при ошибке опыт
помечается неполным. FFmpeg поставляется зависимостью `imageio-ffmpeg`; глобальная
установка и настройка PATH не нужны. Размер зависит от движения и шума сцены.
Для анализа использовать исходные
кадры и числа; сжатое демонстрационное видео — производный материал.

Ранние демонстрации v2 использовали MPEG-4 Part 2, который не воспроизводится
некоторыми системными плеерами. Их можно пересоздать в H.264 из исходных кадров
и сигналов, сохранив оригинальный опыт и его контрольные суммы:

```powershell
python pc_app/export_demo.py pc_app/recordings/<session> pc_app/recordings/exports/<new-export>
```

Нужен новый каталог результата. Экспорт сохраняет ссылку и SHA256 манифеста исходного
опыта, параметры кодирования, временную карту видео и собственный манифест.
Исправленный пример: `recordings/exports/20261111-193110-233ec1f6-h264/demonstration.mp4`.

### Общая шкала и точность синхронизации

Формат **v2** использует монотонное время ПК/QPC; `time_s = (host_ns − start_ns)/1e9`.
Границы опыта едины для камеры, I/Q и демонстрации. WAV дополнительно содержит
150 мс до и после них, чтобы сохранить полные окна Hann и возможность повторного
декодирования на границах. Поэтому длительность WAV немного больше длительности опыта.

Захват S/PDIF идёт непосредственно через Windows WASAPI exclusive, PCM24/96 кГц,
без преобразования частоты и формата. Позиции `IAudioClock` и соответствующие QPC
наблюдаются в процессе записи. Устойчивая линейная модель по скользящему окну
учитывает дрейф и дискретность показаний USB; коррекция вводится плавно. Сохраняются
как исходные наблюдения, так и применённая модель/остаточная ошибка. Время I/Q
относится к **центру** окна Hann, а не к моменту готовности результата спустя 70 мс.
Разрывы устройства и недостоверные часы делают соответствующие I/Q непригодными.

Для D415 выбирается время середины экспозиции, если SDK выдаёт подходящую metadata
и global time. В проверенной конфигурации доступны только `backend_timestamp` и
`time_of_arrival`: используется время передачи в ядре Windows, переведённое из UTC
в QPC через `GetSystemTimePreciseAsFileTime`. Это **не время экспозиции**; ограничение
записано в каждом кадре. Цвет и глубина имеют отдельные исходные метки.

К каждому кадру привязывается ближайший центр I/Q в пределах 15 мс; разность времён
сохраняется. При пропуске нет подстановки или интерполяции. Отдельно хранятся качество
сигнала, качество метки и достоверность расстояния. «Совпало в пределах 5 мс» означает
разницу записанных меток, а **не доказанную физическую точность синхронизации**.

Часы камеры и аудио независимы. Постоянные задержки экспозиции/USB, DSP-фильтров и
приёмника ещё не откалиброваны совместным физическим событием. Поправки времени
по умолчанию 0; положительная поправка переносит источник позже, отрицательная раньше.
Не подбирать их по желаемому виду фазового отклика. После отдельного измерения можно
ввести поправку и сохранить её вместе с опытом; исходные часы остаются доступны.

MP4 имеет постоянный FPS и покрывает реальное время от старта до остановки. Кадры
выбираются по меткам, а не просто склеиваются по порядку. Если в пределах 0.6 периода
кадров нет изображения, выводится «НЕТ КАДРА В ЭТОТ МОМЕНТ»; графики продолжаются
по общей шкале. Непригодные сигналы и переходы через ±180° показываются разрывами.

### Чтение набора для анализа

`analysis.h5` содержит группы:

- `signals`: 100 отсчётов/с I/Q, `amplitude`, `phase_deg` относительно цифровой опоры,
  `phase_tx_deg` относительно TX катушки, `delta_phase_tx_deg` от зафиксированного фона,
  нормированная амплитуда и комплексное отклонение `delta_z_tx_real/imag`.
- `frames`: времена, `distance_mm`, `point_xyz_m`, `point_pixel_xy`, достоверность,
  индекс кадра в `camera.h5` и разность времён цвета/глубины. Дополнительные поля
  `distance_filtered_mm` и `distance_spike_corrected` относятся только к фильтру
  расстояния; XYZ остаётся исходной точкой. Описание фильтра: атрибут `distance_filter_json`.
- `aligned_frames`: индекс ближайшего I/Q, разность времён, его фазы/амплитуды и
  `complete_observation` — одновременно достоверные сигнал, метки и расстояние.
- `audio_packets`: карта индексов PCM в `spdif.wav` на время ПК и позиции устройства.

Порядок комплексных каналов: RX0, RX1, TX катушка, TX усилитель. `iq` имеет восемь
столбцов `[I0,Q0,I1,Q1,I2,Q2,I3,Q3]`; амплитуды в единицах DSP, не в вольтах.
Фазы — градусы в диапазоне ±180°. `phase_valid` проверяет наличие ненулевого сигнала,
но не заменяет будущую оценку SNR. Недостоверные числа сохраняются для исследования
вместе с маской `valid`; их нельзя включать в обучение как обычные наблюдения.
Нет цели/глубины/фона фазы — соответствующие поля `NaN`, а не выдуманный ноль.

`signals/wav_center_sample` связывает I/Q с исходным PCM. Начало окна из 3840
отсчётов: `wav_center_sample − 1919.5`. `signals/nearest_frame_index` даёт обратную
привязку сигнала к видео. Изображения извлекаются из `camera.h5/aligned_color_jpeg`,
числовая глубина — из `depth_z16` с масштабом конкретного кадра в `camera.jsonl`.

Старые опыты **v1 не перезаписаны**. В их аудиометках обнаружены оценки примерно
на 110–120 мс позже получения буфера; они не пригодны для точного анализа связи
видео и фазы без отдельного восстановления времени. Старый AVI также не учитывал
пропуски при воспроизведении. Новые анализ и демонстрация используют только формат v2.

## Управление для ассистента и скриптов

Окно публикует только локальный HTTP API на `127.0.0.1` со случайным портом и токеном.
Адрес и токен: игнорируемый `pc_app/local/control.json`. Не помещать его в GitHub.
Нет CORS; запросы с browser Origin отвергаются. Все изменения выполняются в потоке
Qt, устройства обслуживаются отдельными потоками.

```powershell
python pc_app/labctl.py
python pc_app/labctl.py '{"action":"background"}'
python pc_app/labctl.py '{"action":"item_add","item":{"name":"Медная фольга","material":"медь","orientation":"Плоскость образца параллельна плоскости катушки","distance_mm":"200"}}'
python pc_app/labctl.py '{"action":"record_start"}'
python pc_app/labctl.py '{"action":"record_stop"}'
python pc_app/labctl.py --snapshot tmp/preview.jpg
```

GET: `/status`, `/camera/options`, `/preview.jpg`; POST `/command`.
Команды: `connect`, `disconnect`, `settings` (`values`), `camera_option`
(`sensor`, `option`, `value`), `background`, `plane_point` (`x`, `y`),
`plane_clear`, `plane_fit`, `plane_manual` (`distance_mm`), `restore_geometry`,
`phase_baseline`, `item_add`, `item_select` (`index`), `record_start`,
`record_stop`, `plots` (`values`), `show_dialog` (`camera`, `capture`, `plots`), `close`.
Кнопки и таблицы также имеют имена Qt для автоматизации через доступность Windows.

## Проверки и ограничения текущей версии

Проверка v2: [отчёт окончательной версии](../experiments/2026-11-11-synchronized-recording/20261111-193110-233ec1f6-validation.json).
Записано 358 кадров, 1203 набора I/Q, 12.33 с исходного PCM с запасом на границах;
98.59% I/Q прошли маску качества. Ошибок WASAPI и пропусков по счётчику D415 нет.
Ролик покрывает 12.03 с и содержит один явно пустой кадр на границе записи.
Двенадцать окон I/Q, включая края опыта, повторно вычислены из WAV и совпали
с записанными числами с допуском `1e-10`. Все хеши проверены. Расстояния в пустой
сцене отсутствуют; геометрия и движение с сигналами дополнительно проверены
на искусственных данных. Физическая задержка и точность расстояния этим не измерены.

`python -m unittest discover -s pc_app -p 'test_*.py' -v` проверяет знаковый PCM24, известные независимые I/Q,
скачок времени и восстановление пилота после старта, плоскость/шум/нулевую глубину,
а также обратное чтение видео, WAV/HDF5, дрейф часов, соединение по времени с пропусками
и переход фаз через ±180°. `verify_synchronized_recording.py` выполняет 12-секундную
проверку текущего приложения, WAV с запасом на границах, фаз/амплитуд, видео и хешей.
Он восстанавливает существующую геометрию и фиксирует фон фазы: запускать на
неподвижной установке без цели. `verify_live_recording.py` оставлен как исторический
тест v1, для новых записей его не использовать.

Публичные результаты: [стендовые измерения 10–11 ноября](../docs/measurements/2026-11-10_11/README.md). Исторический отчёт v1 остаётся в локальном архиве.
Первая 12-секундная совместная проверка: 352 сохранённых кадра, 5 пропусков по
счётчику D415, аудио 11.99 с, 0 callback errors; все сохранённые I/Q пригодны по
действующей маске, контрольные суммы совпали. В пустой сцене ложных расстояний не было.
Повторная проверка окончательной версии: 358 кадров, 3 пропуска по счётчику камеры,
12.21 с аудио, 0 callback errors, 98.61% пригодных I/Q. Непригодные интервалы
